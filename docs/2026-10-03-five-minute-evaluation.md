# 5分区間の字幕リーダー検証

## 結論

改善候補の採用は保留。2本目では改善したが、4本目はほぼ変わらず、同じ投稿者の別動画では名札の混入により悪化した。前回の約30〜66秒の結果だけから、他の動画にも安定して改善するとは判断できなかった。

今回はユーザーの指定に合わせ、3本それぞれ本編0〜5分を連続収録した。全編検証ではない。1本目・3本目の長区間再検証は今回の対象に含めない。翌日の他投稿者2本の追検証は[別報告](2026-10-04-other-authors-five-minute-evaluation.md)に記載した。

安定確認後の採点文字は合計5,555字。加重CERは旧版14.87%→候補14.37%で、全体の差は小さい。認識開始直後の画像も含める補助集計は21.39%→13.95%。この補助値だけを改善の結論に使わない。

## 対象と方法

- [2本目・顧客調整](https://www.youtube.com/watch?v=a6yGrlEas-4)：全長24分57.521秒、本編0〜300秒を対象。再生303.810秒で一時停止し、書き込みを待って回収後にアプリを停止。全編終了の判定は使用していない。
- [4本目・障害報告](https://www.youtube.com/watch?v=DHX3ZDRP4Go)：全長8分21.601秒、収録は305.907秒まで。採点の予定時刻は5〜300秒。
- [別動画・お偉いさん介入](https://www.youtube.com/watch?v=2MEgE9xZsGs)：全長5分56.801秒、収録は306.040秒まで。採点の予定時刻は5〜300秒。

PixelCopyによる評価用の原画像取得を、OCRが処理中かどうかに依存させず、約1秒間隔で行った。通常の診断記録の120秒・64MiBの循環保存は変更せず、明示したデバッグ検証モードだけ古い記録を保持する。上限到達時は既存記録を消さず失敗として停止する。

ミュートボタンを実際の画面で確認してタップし、表示の消失とmuted=falseを確認してから0秒への巻き戻しを許可した。巻き戻し直後の再生コントロール・シーク待ち画像は採点から外した。4本目では巻き戻し要求後に広告が入り、最初の観測は広告だった。開始時刻には、広告終了後の本編0秒への巻き戻しを示す元のplayback_state記録を用いた。

OCR結果を見る前に5秒ごとの採点予定時刻を決め、最も近い原画像からCodexが字幕を独立転記した。近接するもう1枚を、文字画素の一致度で選んだうえで目視確認した。2枚ある場合、先の画像を認識の安定化に用い、後の画像を採点した。近接する一致画像がない短い字幕は1枚で採点し、失敗例として除外していない。2本目の240秒付近の広告移行黒画面は除外した。名札・小道具のラベルは正解字幕に含めない。小さな反応字幕は含める。

各APKへ同じ画像・単調時刻・正解を入力し、同じtest APKで実際の日本語ML Kit、領域選択、再認識を実行した。入力manifestとAPKのSHA-256、時刻、正解文の一致を検査した。基準は9ab3ebfd、候補は38e681d2。候補の認識設定は収録・採点のために変更していない。

CERは既存のcaption_comparison_key_cer。句読点等の正規化後の置換・挿入・欠落の編集距離を正解文字数で割る。読み上げの音声誤り率ではない。5秒ごとのサンプル間に現れる短い字幕の見逃しは、この集計だけでは評価できない。再生時刻の観測にも約1秒の遅れがあり、フレーム単位の時間保証はない。正解はCodexによる原画像の目視転記で、独立した人による確認は未実施（human_verified=false）。

## 残った問題

2本目では名札「協力会社さん」の除外が効いた。一方、約20秒の小さな反応字幕「目の前の事で／手一杯」は候補で欠落した。

4本目では約125秒の「チームリーダー／メンバー」の余分な混入が11文字分増えた。約295秒の短い字幕は候補で拾えるようになったが、安定後の全体CERを改善するには至らなかった。

別動画では採点した7か所で「お偉いさん／有識者」などの名札が追加され、編集距離が合計56増えた。これらの字幕本文の認識結果は基準と候補で同じだった。字幕候補を早く通す変更が、名札も早く通してしまう。現在の短い名詞・配置に基づく名札除外は、文字認識によってラベルが1行に結合された場合などに不十分。

「システム→ジステム」などの文字自体の誤認識も残る。領域の候補判定を緩めるだけではこの種類の誤りを解消しない。次の実装修正は、字幕と名札の画素上の特徴を区別する方法、低解像度の文字へのOCR入力処理、反応字幕を残す条件を別々に評価する必要がある。今回の結果を見て同じ動画に追加調整する作業は行っていない。

実再生のTTS callbackは上表の通り。2本目には広告中の読み上げも1要求あったため表の本編集計から除外した。区間境界で送信/完了数が異なる場合がある。録音の聴取、発音品質、全字幕イベントの読み上げ完遂率、S25実機の温度・電力は未検証。リプレイ内のTTSは即時完了を模擬しており、実際のTTS callbackとは別物。

## 保存した結果

6件のリプレイJSON、3件の比較JSON、3件の連続収録監査、3件の実再生TTSログ、画像SHA-256と正解を含むmanifest、window-summary.json、window-checks.json、数値再集計スクリプトを保存。単体テスト151件成功、デバッグ/テストAPKビルド成功、6件の実OCRリプレイ成功、4本目・別動画の5分到達判定成功。2本目は専用の停止手順で回収し、全編収録成功とは扱わない。

画面収録と検証画像はユーザーの指示で分析完了後に削除した。画像を含む過去のZIPも削除した。削除後は保存済みJSONから数値を再集計できるが、同じ画像を使ったOCRの再実行には再収録が必要。削除数と容量は画面収録削除記録.jsonに残す。

削除完了：Mac側3,989ファイル、2.88GB分（ファイルの論理サイズ合計）。実際の空き容量増加はファイルシステムの割当やスナップショットによって異なる。エミュレーター内の診断PNGとOCR再入力画像も削除。SDK・ビルド環境・ソース・APKは保持。
