# PP-OCRv5 mobile のAndroid実装

PP-OCRv5 mobile recognition を字幕の再認識に標準で使用する。広い動画画面から字幕候補を検出する段階は従来のML Kitを使用する。字幕の役割判定の実験は含めていない。

## 認識経路

1. ML Kitで全体・上部帯の文字を検出し、既存の字幕選抜処理で字幕帯を選ぶ。
2. 元画像から字幕帯を取り出し、ML Kitで行の座標を得る。
3. 行ごとにPP-OCRv5で再認識する。行高の50%を左右、35%を上下に余白として足し、隣接行との中点で上下の余白を制限する。高さ48、BGR CHW、動的幅320〜3200、正規化とCTCデコードを端末内で行う。
4. 確率0.65以上、元文字との長さ比0.5〜1.5、類似度0.50以上を満たす行を採用する。これらは誤採用を抑える固定の安全弁であり、精度保証ではない。
5. 既存の字幕選抜、複数フレーム統合、重複抑制、読み上げ順序処理を続ける。最終選抜の候補グループがすべてPP採用行である場合は類似度0.50・長さ比0.5〜1.5を使い、壊れた粗いOCRに正しい訂正が棄却されることを防ぐ。同じ行数、行の隣接・整列、途中までの文字への縮退禁止は維持する。既存の2行→3行補完判定は変更しない。ML Kitだけの結果は従来の0.80・0.85〜1.20を維持する。

モデルの確率はML Kitの信頼度と別の尺度として記録する。行の位置とML Kitの信頼度を保ったまま文字を置換する。PPが1行以上採用された字幕帯では白文字マスクによる追加OCRを省く。未採用の行はML Kitの文字を保つ。ML Kitが検出しなかった行は、この実装だけでは復元できない。

モデルの初期化・推論失敗はML Kit結果へ復帰する。初期化に失敗したセッションでは再試行を繰り返さない。モデルは遅延読み込みし、単一ワーカー、推論2スレッドで実行する。Activity/Serviceの終了時に所有セッションを閉じる。共有のOrtEnvironmentは閉じない。

診断イベントの `backend` は `mlkit` または `ppocrv5`、`model_probability` はPPの採用行平均であり、未使用時は-1。混在した結果も `ppocrv5` とする。行ごとの `model_probability` はPP未採用行では-1であり、混在した行グループの選抜条件は緩めない。手動ROIの画面共有経路も再認識にPPを使用する。

## 固定モデルとライセンス

公式PaddlePaddle配布の `PP-OCRv5_mobile_rec_onnx`、revision `ed152b8b495f84de93cda5709d768548a9127622` を使用する。

- 認識モデル16,534,782 bytes、SHA-256 `da72dc72ca4dc220df0dfde68c1dedc31c58d3e76a25871122e5056227d50092`。
- 元の `inference.onnx` を `assets/ppocrv5/recognition.onnx` として格納する。元URL・ハッシュは同ディレクトリの `source-provenance.json` に固定している。
- 公式 `inference.yml` の `PostProcess.character_dict` をJSON配列へ変換し、先頭にCTC blankの空文字、末尾に空白を追加する。18,385要素。変換済み辞書SHA-256 `14ccb8e120e701464bd3084acf3b398ffee767e515477ad27d3c80fd5996c180`。
- モデルApache-2.0ライセンスを同梱。ONNX RuntimeのMITライセンスを `docs/licenses/ONNX-Runtime-LICENSE.txt` に保存。APKにも `assets/licenses/` にMITライセンスとversion1.30.0の第三者通知を同梱。
- ONNX Runtime Android 1.30.0、ML Kit Japanese 16.0.1。認識時のモデル配信・クラウドOCRは不要。
- ONNXを非圧縮APK assetとしてメモリマップする。モデルの別コピーを内部ストレージへ抽出しない。ロード前にサイズとSHA-256を検査する。

## ビルドと負荷

`gradle :app:testDebugUnitTest :app:assembleDebug -PcaptionAbis=arm64-v8a` でARM64向けAPKを生成する。省略時は依存ライブラリが提供する全ABIを含む。1.0.2-preview / versionCode 33。

モデル16.5MBに加え、ARM64のONNX Runtime本体は約33MBである。ML Kitも残るため、モデルサイズだけがAPK増加量ではない。全ABIのAPKを配布する場合はさらに増える。配布時は端末のABIに合わせたAPKまたはApp Bundleでの分割を検討する。

検証の数値と限界は実装レポートへ保存する。既知動画の手動行切り出しで得た11.02%→3.21%を、アプリ全体の誤り率として扱わない。エミュレーターで実機の電池・熱・音声遅延を保証しない。

辞書は `tools/models/convert_ppocr_dictionary.py inference.yml characters.json`（PyYAML 6.0.3）で再生成できる。公式設定の固定SHAを検査し、同梱辞書と同じハッシュになることを確認した。

## 実装検証結果

221単体テスト成功。API36 ARM64エミュレーターでモデル読み込み、日本語3行の完全一致、モデル欠損時のML Kit復帰を確認した。既知のプロマネコ動画I5U-NPzXCxsの2:00〜7:05を315参照画像・欠落0で採取し、正解を固定した30採点地点＋30直前画像で、同じテストAPKを使って自動字幕処理を比較した。CERは53/991（5.35%）→38/991（3.83%）。13地点改善、8地点悪化。処理中央値は524→984ms。ARM64 APKは64.65MiB。

同じ開発用動画で接続部を修正した結果であり、新規投稿者への一般化や実機の音声・電池・熱は未評価。発話は即完了する部品リプレイで、ライブ発話の誤り率ではない。背景文字の混入・章タイトルの検出漏れは残る。人工Latin ABC123はABCIZ3となり、完全認識ではない。
