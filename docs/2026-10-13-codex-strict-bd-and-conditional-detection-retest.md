# Codex実験依頼：PP-OCRv6 Recognition固定のB/D比較と「3行のみv6検出」の実現性（2026-10-13）

**状態：実験計画・Codexへの実行依頼。Mac実行、Galaxy S25実機、可聴音声の新計測は未実施。**
製品改修と混同しないこと。ユーザーはP1〜P4の追加検討を終了し、OCR固定D・UI削除をPR #52で進めている。この実験ではP1〜P4を再開せず、一般設定にOCR切替UIを再導入せず、mainへのマージやAPK Releaseをしない。

## Codexへの目的・優先順位

1. **B：ML Kitで位置検出 + PP-OCRv6 Smallで文字認識**と**D：PP-OCRv6 Smallで位置検出 + PP-OCRv6 Smallで文字認識**を、元画像・正解字幕・時計・OCR辞書・モデルSHAが同じ条件で比較する。
2. 以前「名札・3行字幕」と呼んでいたのは**1つの検証動画の名称**であり、**実際の3行字幕だけを抽出したスコアではない**。真値の字幕行数（1/2/3以上）と、名札・章切替・UI・図中文字などの非字幕文字の有無で層別して、Dの利点の原因を検証する。
3. 「Bを普段使い、3行らしい場面のみD」という条件付き手法について、正解行数に依存した**oracle上限**と、**Bの出力からだけ判定可能なルール**を区別する。追加推論の平均負荷・発話遅延が実用的かを見る。
4. 既報の「未使用動画でB→D約+787.5ms」は**Androidエミュレーターの1枚あたりフルOCRパイプライン中央値の差**。v6 Detection単体はML Kit公開認識済み行の40.3msに対して220.1msで**約+179.8ms**。これをGalaxy実機の遅延、音声遅延、常時0.8秒の追加待ち時間と同一視しない。
5. 結論は「B固定／D固定／条件付き／判断保留」の4案を根拠と負荷制約で比較。判定用未使用素材がなければ、既知99枚での探索結果だけを出し、最終採否は保留する。

## 1. 第一段階：同一99枚の正確な再現（Androidエミュレーター）

- 既存の `tools/four-way-evaluator/run.py` と `tools/image-evaluator/run.py`、`tools/four-way-evaluator/analyze.py` を利用。先に保存済みレポート `summary.json` を再集計し、過去のB/D数値（CER、raw CER、SER、各stage実行回数、中央値/p95）と照合。
- `docs/pr33-four-way/evidence.tar.gz` が保存するデータとMacローカルの元PNG/正解を検証する。画像が存在しないなら「再推論不能」と明記し、再収録画像を**過去の同一画像**と偽らない。全フレームのID・フレームSHA・参照文字列・mono_msとデータセットmanifest SHAを照合。
- 現行run.pyはA/B/C/Dの全4方式を回すので、B/Dだけを実行する**診断用オプション**を追加してもよい。製品設定・デフォルトを変更しない。オプション追加後は実行・選択したモデル、`mlkit_calls` と `detector_calls`、`recognizer_calls` をテストで確認：BはML Kit検出、DはML Kit呼出ゼロ。
- 少なくとも**3反復**、初期化済みの定常状態とcold startを分けて、順序をB→D、D→B、B→Dと入れ替える。各条件で実行時刻/温度/事前warmupを記録。以前の `analyze.py` は反復2回固定なので、3回分を読むよう拡張するか、別レポートに3回分を集計する。2回分だけを3回分と偽らない。
- フル処理（画像取得後のcoarse→候補選択→crop→refine→選別）、検出単体、v6認識単体、呼出回数・1画像あたり分布、warm中央値・p95・p99、初回コスト、PSS/RSSを別集計。ML Kitは内部detectorのboxを直接返さず公開済み認識行との比較になる点を注記。
- 同一モデル・辞書・画像を使うがBとDでは検出位置・候補数・再認識数・文字幾何が異なる。**B→Dは製品処理経路の比較であり、検出ネットワーク単体の因果効果とは言い切れない。**
- 診断リプレイのTTSは即時完了シミュレーション。実音声の開始・字幕が表示されている間の取り逃し・長時間発熱は結論に使わない。

## 2. 第二段階：実際の3行字幕と背景文字混入を分離

参照正解を先に固定し、各フレームにモデル出力を見ないで付与するラベル：
- `gt_caption_row_count`: 0、1、2、3、4以上、判定不能。**真値の複数行表示**で数える。字幕テキストの改行、`caption_lines` の矩形、画素を照合。自動改行やOCRが分割した行数は真値と混同しない。
- `noncaption_text_visible`: 有／無／不明。名札、時計、章切替、UI、図中文字を可能な範囲で細分類。
- `caption_position`: 上／中央／下／複数、`caption_duration_ms`（表示間隔が分かるとき）、`three_row_visibility`（短時間・一時・常時）。
- 個々の動画では「名札あり × 3行」「名札あり × 1〜2行」「名札なし × 3行」「名札なし × 1〜2行」のクロス集計。少数群は `n` を必ず表示し、分母ゼロなら「未評価」。一つの動画の全フレームが3行だと決めつけない。

各層について**B/DのCER、完全一致画像、非字幕混入、字幕の完全見逃し、誤読した数字・否定、文字列の並び、OCR処理時間、D優位・B優位のフレーム例**を必須出力。
- 原画像に見える字幕行数の推定自体が曖昧なら `unknown` を許し、推定値で学習・検証を汚さない。
- 反復フレームが多い場合は画像件数に加え**固有の字幕イベント件数**を提示。同一字幕の繰り返し画像を独立データとして扱わず、信頼区間は動画・イベント単位で計算する。
- 特に以前の名札動画のB 12.84%→D 0.94%の改善が、3行か、名札・固定文字の混入除外か、別の効果かを**逐一反例で確認**。因果要因が分離できなければ「要因未確定」と報告。

## 3. 第三段階：条件付きDの机上試験（本番実装しない）

3種類を区別して評価する。

**(A) B固定、(B) D固定**：前段の実画像に対する結果。

**(C) oracle「真値が3行以上ならD」**：正解ラベルを使った**上限の試算**。この判定は本番には使えないことを強調。oracleよりB/D以外の不正な文字列を作らない。処理時間は判定前のB実行が不要と仮定した上限と、Bを先に走らせた場合の合計を別表にする。

**(D) deployable「Bの読み取り結果だけで3行を疑う」**：ML Kitの公開OCR行とその位置・信頼度・過去フレームの非機密メタデータだけで判定。Bの2行出力の裏にある見逃した3行目を原理的に直接知れない。ルールは既知動画で定めて固定し、未使用動画では絶対に調整しない。GT行数はトリガ作成にも閾値調整にも使わない。
- ルールのrecall/precision、真の3行の見逃し、誤発動率、追加v6 detection回数、1フレームにつきB後にDを追加した場合の**実負担（B時間＋D時間＋遅延）**を採点。
- D実行対象は背景文字が多い場面も候補になり得るが、名札リスクと3行検知を同一指標にしない。
- 単純なB/D出力の机上選択は、**実際のライブ切替効果や実音声の改善を証明しない**。既知99枚ではoverfit、しかも連続処理の時間経過は再現しないので、prodへの分岐追加は禁止。

## 4. 第四段階：完全未使用の動画で追試

- 99枚中の `heldout` も使用済み。許可の取れた**新しい日本語字幕動画を複数**、できれば**3本以上×各5分以上**用意。特に本物の3行字幕、1/2行、名札が同時に出る例、名札なし3行、上部の3行、短く表示される字幕、数字・否定、空白区間を含める。3行群が不足したら結論は「3行未評価」。
- 事前に対象動画・再生区間・撮影方法・画質・表示解像度・向き・フレーム抽出規則を固定。CCはOFF、広告・プレーヤー操作UIを除外。PixelCopyの実フレームと正解アノテーションを別の人が監査できる形で保存。
- 参照字幕はモデル出力とは独立に原画から転記し、可能なら人手で監査してから評価。動画編集等で意図的に3行を合成した素材ならその出自も明記、自然動画と混在集計しない。
- 補助OCRのモデルや閾値を未使用素材の結果を見て調整した場合、その素材は検証セットから開発セットに移し、さらに別の未使用素材が必要。
- Galaxy未接続で元PNGのみの場合は静止画比較まで可能だが、端末の実動画/TTS測定は「未実施」。

## 5. 第五段階：Galaxy S25の実端末でライブ確認（ADB接続・許可時のみ）

- **`adb devices -l` で認可済みの実機を確認してから**ユーザーのGalaxy S25で測定。端末がなければ接続失敗を記録し、MacのエミュレーターやM4をGalaxyの代わりにしない。
- 一般向けPR #52の設定はD固定なので、試験用APK/診断Activity内でだけB/Dを選べる実験フックを設ける。テスト用フックが使えない場合は、B/Dのライブ比較未実施と明記する。古い方式に一般設定を戻したり、既存のユーザーデータを無断削除・無断上書きしない。
- 同じ動画・同じ再生位置・画質・画面方向・省電力設定・初期化/ウォームアップ状態で、BとDそれぞれ**3回以上**、B→D→D→B等順序を分散。画面録画/PixelCopyによる正解画素を確認し、実際に取得した画像の差は無視しない。録画・診断ZIPは端末とMacローカルに保管。
- 必須：`capture_poll`のrequested/busy_skip（ログ有効時のみ）、PixelCopy要求/完了、OCR開始/終了、stage呼出数、字幕イベント初出、TTS request/`onStart`/complete/drop、同時音声録画の**可聴開始**。可聴音声が取れなければ「未測定」。誤読みと重複、短時間字幕の取り逃しを**イベント単位**で独立採点。OCR平均だけでは採用判断しない。
- 480msは*試行周期*であり、約1,139msは*エミュレーターの中央値*。フレームを毎480ms確実に処理する保証ではない。1,139msに対して2回程度busy skipする模式例をGalaxy実測と書かない。
- warm中央値だけでなくp95、90%／95%イベントの字幕出現→可聴発話開始の遅れ、字幕が消える前に読み始めた率、画像取得抜け率、実端末のPSS/温度/消費電力を可能な範囲で報告。計測手段と測定不能項目を明記。
- Galaxyの実機でBの効果が十分でDが遅いと確認されたときのみ、条件付きDの実機試作を**別PR**として提案。P1〜P4は再開しない。
