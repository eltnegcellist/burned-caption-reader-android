## 1. 方針と到達点

**D（PP-OCRv6 Smallの文字位置検出＋文字認識）を精度優先の採用候補として改善する。まず計測を補い、同じ画像に対する重複推論を減らす。字幕欠落・混入の修正は別工程で検証し、Galaxy S25で受入条件を満たしてから既定変更とマージを判断する。**

Dの基本推論・モデル同梱・設定切替は実装済みである。本計画は新規導入ではなく、比較版を継続再生に使える品質へ整える計画とする。最初からモデルを再学習したり、別モデルへ置き換えたりしない。

以下を全工程で守る。

- DではML Kitを生成・実行せず、v5にも自動で切り替えない。モデル異常は利用者にエラーを示す。
- v5のモデル・辞書を変更しない。A/B/Cと2つの独立スイッチを比較・切戻し用に保持する。他のPRを変更しない。
- 字幕選別、時系列合意、安定化、発話順、台帳、TTSの既存経路を共用する。D専用の動画ID・字幕語句の例外リストを作らない。
- 性能だけを改善する変更と、選別・認識品質を変える変更を別コミット・別計測にする。
- 当面の既定はA、PRはDraftのままとする。本計画書を保存することは、Dの既定化・mainへのマージの実行ではない。

## 3. 現行経路と改善後の設計

現行Dの大きな流れは次の通り。

```text
PixelCopy原画
  → coarse画像のv6検出＋各行のv6認識
  → 下部字幕の回復（必要時）
  → 共通trackerで字幕bandを選別
  → bandの拡大画像で再びv6検出＋各行のv6認識
  → 共通の再認識採用判定
  → consensus／stabilizer／発話順／台帳／TTS
```

`V6ComparisonOcrEngine.recognize()`と`refine()`は、Dではどちらも`detectAndRead()`を呼ぶ。`SharedPlayerActivity.refineBands()`から再認識するため、同じ原画の位置を繰り返し検出する。24行の上限は各OCR呼出に適用され、画像全体の総試行上限ではない。

改善後は、同じ原画に属する検出候補を再認識まで引き継ぐ。

```text
PixelCopy原画＋frame_id＋generation
  → coarse画像でv6検出
  → 検出四角形・DB score・座標変換を保存
  → 粗読／共通trackerで字幕候補を選別
  → 候補を原画へ戻し、必要な行だけ原画から切り出してv6認識
  → 不足を示す条件があるbandだけ追加検出・認識
  → 共通の採用判定／時系列処理／TTS
```

粗読の文字列は既存trackerに必要なので、最初から全ての粗読認識を省略しない。coarse検出と拡大band検出は解像度も範囲も違い、後者が追加行を見つける可能性がある。したがって「1画像につき検出は必ず1回」に強制せず、追加検出の根拠・範囲・回数を記録する。

### 同一画像のデータ契約

新しい中間データ型（仮称`FrameOcrSnapshot`／`DetectedTextRegion`）には、次を持たせる。

|データ|用途・制約|
|---|---|
|frame_id、generation、mode、原画サイズ|別画像・seek前・旧modeの結果を使わない|
|入力変換情報|原画→coarse→bandの座標を往復できるようにする|
|検出四角形、矩形、DB score、候補ID|回転cropと読順を保持。文字列が空でも診断に残す|
|認識文字列、PP確率、認識crop情報|認識と検出の証拠を分離する|
|再利用・追加検出の理由、試行数|推論削減による見逃しを追跡できるようにする|

原画Bitmapの所有者は画像処理単位で一本化する。workerが使用中の原画をrecycleせず、成功・失敗・取消の全経路で一度だけ解放する。最初の実装では別時刻の画像間の認識キャッシュを導入しない。

## 4. 実装工程と成果物

|工程|優先度|作業|完了条件|
|---|---|---|---|
|P0：計測・正解監査|最優先|画像・候補・行ごとの段階計測、欠落理由、認識確率を記録。既存正解を監査する|欠落が検出・crop・認識・選別・発話のどこで起きたか追える|
|P1：重複推論の削減|最優先|同一画像の検出候補再利用、原画crop、限定追加検出|現行Dとの精度比較に合格し、処理時間と回数が減る|
|P2：字幕欠落・混入の改善|高|短い行・3行の完全性、章カード・名札・図ラベルの選別を改善|回帰例で改善し、新しい固定検証セットで悪化しない|
|P3：Android運用の安定化|高|model lifecycle、busy・取消・seek・設定切替、原画解放、初期化・メモリを確認|実機の連続再生と切替試験が通る|
|P4：配布・採用判定|最後|arm64比較APK、実機受入、必要なら既定Dへの変更|全受入条件を満たし、採用判断を記録する|

### P0：結果の出所と欠落段階を記録する

累積時間だけでなく、画像単位の検出・DB後処理・crop・行認識・選別・時系列処理の時間を取得する。raw候補数、形状除外、24試行上限、空認識、band採用／棄却と理由を残す。計測・画像保存の負荷は処理時間と区別する。

現行Dの`OcrLine`生成はPP確率を`confidence`へ換算しているが、`modelProbability`は渡しておらず、glyph高さも未指定なので矩形高さが使われる。この二点を明示的なmetadataとして記録し、ML Kitのsymbol由来値と同等と見なさない。計測を補うコミットでは、既存の採用閾値を変えない。

また、`OcrRefinementSelector`の`trustedPp`は現在`ppocrv5`だけを対象にし、MLとの行単位の合意を前提に緩い採用条件を使っている。**Dのbackend名を追加するだけで、この緩い条件を移植しない。** DにはMLによる合意確認がないため、P2で同一画像の一致・幾何・認識確率の根拠を評価してから扱いを決める。

成果物：診断schema、stage別時間、欠落事例一覧、人が監査した正解差分。Aの内部初期化・認識回数の未計装も、比較用に必要な範囲で計測を補う。

### P1：同じ画像の候補を再利用する

1. Dの検出と行認識を内部APIとして分け、中間データに四角形・変換情報を保持する。A/Bの経路は維持する。
2. coarse検出候補を原画座標に戻し、共通trackerが選んだbandに対応する行を原画から切り出す。padding・隣接行境界・回転cropを保つ。
3. 対応候補がない、境界を跨ぐ、行の不足が疑われる等の場合だけ、該当bandを追加検出する。初期は既存の追加検出を保ち、削減条件をdevelopmentで段階的に有効化する。
4. 同じcropを同じ設定で繰り返し認識しない。粗読と高解像度原画cropは別入力なので、無条件に文字列を流用しない。
5. 1画像の総試行数を計測する。予算を設ける場合も、短い字幕を幅の小ささだけで後回しにせず、候補超過を診断で明示する。

比較時は`D_current`と`D_candidate`の実装revision・再利用方針を記録する。A/B/C/Dの意味は変えず、両Dともv6検出＋v6認識である。最適化の有効化はdebugの比較設定で行い、製品UIには内部調整項目を増やさない。

成果物：座標変換・候補引継ぎAPI、Dの原画行認識、追加検出条件、現行Dとの同一入力差分。

### P2：字幕の完全性と役割判定を改善する

対象の回帰例は、3行字幕の中段欠落、短い「まあ1日1回」の欠落、小さい下部字幕の完全空出力、章切替カードと図ラベルの混入である。語句を修正ルールに埋め込まない。

- P0の診断で欠落段階を確認する。独立診断では字幕行Recallが100%でも、全失敗画像の検出が正しいと保証されたわけではない。
- 同一字幕群の行間隔・左右の揃い・文字サイズ・時系列の同期を使い、短い行を周囲の本文と合わせて評価する。全ての短い名詞行を救済する変更にしない。
- crop内の既存候補行と選択された行を対比し、再認識の採用で行を落としていないか確認する。現在の2行→3行回復だけでは足りない例を、名札追加の負例と組にして検証する。
- 章カードの中央配置・サイズ・場面切替との関係を調べる。中央／上部という理由だけで通常字幕を除外しない。長く表示された文字を自動で章カードと決めない。
- PP確率とML confidenceの数値を直接比較しない。PPの採用基準は監査済みdevelopmentで評価し、検証セットを見てから閾値を調整しない。

共通selectorを変更した場合は4方式全てを再測定する。Dだけが改善してA/B/Cの欠落・名札混入が増える変更は採用しない。モデルraw出力・正規化CER・Raw CER・選別後CERを分けて報告する。

成果物：原因別の修正、正例／負例の回帰テスト、動画別・方式別の差分表。

### P3：連続再生とmodel lifecycleを整える

モデルと辞書の固定SHA-256、CTCクラス一致、DB出力shapeのチェックを維持する。初期化はmain threadで行わず、完了時のgenerationを確認する。不要なmodeのsessionを先に作らない。

現行samplerは480 ms間隔で、busy中は画像取得を行わない。処理を速く見せるためにsampling間隔だけを広げない。予定sample、取得、busy skip、処理完了、TTS要求を別々に数え、表示時間の短い字幕を観測できた割合を評価する。

取消・pause・seek・動画変更・mode変更・Activity終了では旧画像の結果を新しい状態へ渡さない。workerの取消／終了とBitmap解放の契約を明確にし、callback未通知でbusyが残る経路や、closeとの競合を試験する。初期化先行・ORT thread数・arena等の変更は、実機profile後に一項目ずつ試す。

成果物：lifecycle試験記録、cold/warm初期化時間、PSS/RSS、sample coverage、連続再生・発話の診断。

### P4：配布APKと本採用を判断する

比較APKはA/B/C/Dと旧モデルを保持し、Galaxy S25向け`arm64-v8a`版をビルドして容量を実測する。比較中にv5を削除しない。D専用の小容量製品flavorは、別途採用判断が済んだ後の作業とする。

既定Dへの変更は最終工程で、既存利用者が保存したmodeを上書きしない。Aへの手動切戻しを残し、D失敗時にbackendが分からない自動切替をしない。PR #33のbaseがmainではないことを踏まえ、依存するbaseの変更・CI・実機動作も確認してからマージ順序を決める。

## 6. 検証データと試験方法

**今回失敗を見た動画は、次の実装では未使用検証用と呼ばない。** 既存99画像は固定された回帰セットとして保存する。以前のheld_out動画`mfsi8GfAvEA`も、修正の判断材料に使った時点でdevelopment／回帰へ移す。元の比較レポートやmanifestは上書きせず、新評価で役割を記録する。

新しいheld_outには最低3動画・2投稿者を事前選定し、通常の1～2行字幕、3行・短い行・数値／否定、小さい下部字幕、上部字幕、名札・図・章カード、本文なし場面を含める。各必要カテゴリに最低10事例を確保し、不足分は追加収録する。動画ID・区間・除外理由・画像hash・正解・矩形を推論前に固定し、人の監査を行う。原画像のない既存例は再収録が必要である。

精度は、同一PixelCopy画像を現行D・候補DとA/B/Cへ入力して評価する。モデル／選別／発話要求の誤りを混ぜない。CERは正規化とrawの両方、SERの単位、完全見逃し、部分的な行欠落、空字幕への出力、名札・図混入を明記する。検出はIoU matching、認識は同じ手動cropで独立採点する。

Galaxy S25ではA/B/Dの同じ動画区間を通常再生し、試験順を交代して各3回計測する。精度用の同一画像replayと、ライブ再生のsampling・処理・発話試験を分ける。ライブ再生の画像が完全一致したと主張しない。OS／APK／model hash、動画画質、端末向き、輝度、電池状態、充電状態、TTS設定、室温を記録する。

30分の連続再生では、同じ固定区間を繰り返し再生して時系列の遅延・メモリ・熱・電池消費を取得する。seekで画像・字幕状態はリセットし、model sessionの継続条件を全方式で揃える。TTSは要求・開始・完了・破棄と実音声を照合し、重複・順序違反・字幕初出から発話開始までの遅れを確認する。

## 7. 受入条件

以下の数値は**計画上の目標であり、達成済みの実測値ではない**。評価定義と閾値は候補を採点する前に固定する。達成できない場合はDを既定にせず、失敗理由を残す。

|領域|受入条件|
|---|---|
|Dの構成|全推論でv6 det＋v6 rec、ML Kit呼出0、モデル・辞書hash一致、silent fallbackなし|
|既存回帰|監査後の同じ正解で、候補Dの動画別正規化CERが現行D以下。Raw CER・完全見逃し・行欠落・混入も増加させない|
|性能最適化の目標|同一エミュレーター・同一画像で現行D比のmedianを30%以上短縮し、各動画のp95を悪化させない。エミュレーター値は実機値と分ける|
|新held_outの精度|全体正規化CERがAより低い。動画別・重要カテゴリ別に完全見逃しと本文混入をAより増やさず、Raw CERも報告する|
|内容の安全な保持|数値・否定の新たな欠落や置換を導入しない。発話に至った重要誤りは個別に原因・採用可否を確認する|
|実機の処理目標|Galaxy S25のwarm画像処理median≤480 ms、p95≤960 ms。480 msのsampling設定を維持して評価する|
|実機の発話目標|新字幕の初出観測から対応するTTS開始までのp95≤1,500 ms。要求時間と開始時間を区別する|
|ライブcoverage|取得・処理された字幕イベントの割合がAより低下しない。遅い処理によるskipを隠さない|
|メモリ・安定性|30分再生でcrash／ANR／OOM／session・Bitmap残留の増大なし。PSS/RSSと初期・終盤の同一区間の遅延を報告する|
|TTS・切替|既存の重複防止・順序・取消が回帰しない。再生中の4方式切替、pause／resume、seek、動画変更、終了が成功|
|熱・電池|A/B/Dの同条件の実測を比較し、熱による遅延増大と電池負担を採用判断に含める。電力が最適という主張は実測なしに行わない|
|CI・成果物|既存JUnit・runner・台帳回帰、新しい座標／取消／行完全性の試験、Android build、実モデルinstrumentationが成功。APKと全結果のhashを保存|

実機の受入目標を満たさず、精度だけ良い場合は、Dを選択可能な実験構成として残す。速度と精度の両立ができる字幕形式ではBを代替候補にし、既定Aを維持する。
