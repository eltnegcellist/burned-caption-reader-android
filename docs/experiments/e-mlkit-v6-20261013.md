# E案実装とB/D/E同一99画像比較（2026-10-13）

**E案を試験専用に実装し、B/D/E各3反復、計891画像推論を実行。** 全体CERはB 10.77%、D 5.62%、E 7.07%。これはGTで良い文字列を選んだ前回5.93%のoracleと異なり、GTなしの固定ルールをAndroid上で実行した実測。正解全文、原画、モデル、APK、署名鍵は公開しない。通常アプリはD固定のまま、P1〜P4は再開していない。

## Eの実装範囲と事前固定

- 基準はPR #54の`89e2a5f`。同じworkspaceの専用実験ブランチ`codex/e-mlkit-v6-experiment-20261013`で実装。PR #54のブランチ・別作業treeは変更していない。
- Eの検出／認識engineはBと同じ明示`CaptionOcrEngines.create(context, REC_V6)`。EはML Kit検出／粗認識＋v6 Small refine。v6検出の追加やD再実行はない。各画像の累積／増分でE/Bのv6 detector calls=0、DのML Kit calls=0、双方のv6 recognizer実行を検査した。
- `ExperimentalEPolicy`は`app/src/experiment/java`。GradleのandroidTest/test source setだけに追加した。通常APKにはEのdex文字列がなく、試験APKにのみ存在することを確認。通常app APKは前回と**byte-for-byte同一**。AppPreferences、SettingsPanel、SharedPlayerActivity、production OCR／字幕選別ソースを変更していない。
- 原画・GT・行数／背景ラベル・モデルSHAは前回と同じ。EにはGT、動画名、dataset名、Dの出力を渡さない。コードは最初のE推論前にSHAを固定し、E結果を見て閾値を変更していない。過去99枚の失敗を知ったうえで設計した探索なので、独立blind評価ではない。
- **背景候補処理**：幅≤.50、高さ≤.12、2〜12字の日本語名詞型、句読点／文末表現なしの行に対し、別の隣接2行字幕が存在する場合だけ除外。幅≥.50のanchor、字高比≥1.25、距離>max(.10,3字高)を要する。結合名札を対象にし、上／下という位置だけでは棄却しない。短い実字幕を誤って除外する一般化リスクは未使用素材で未検証。
- **v6修正採用**：既存Bの選別をfallbackに保持。backend=`ppocrv6_small`、粗文と同じ行数（1〜3行）、隣接幾何が成立、全行の実PP probability≥.65、文字数比.50〜1.50、類似度≥.50のgroupから選ぶ。Eが新たに採用する数字／否定の変更には全行probability≥.90を要求（fallbackに残す既存Bの選別は従来のままで、全経路の意味的無誤読を保証しない）。ML Kit confidenceでPP probabilityを代用しない。読み直し全採用ではなく、条件外では元のB選別へ戻す。
- 背景除外はtracker前に行うため、背景bandのrefineを減らせる。修正選別は既存refine後に行い、OCRを追加しない。通常の選別時計にE policy時間を加算し、e_policy_nsを別に保存する。二重加算しない。

## 再現・検査

同じworkspaceのruntime/env.sh（前回の確認済みJDK/SDK/Gradleとworkspace cache）を使用。既存v6 assetsを再利用し、モデル／辞書SHAをAPK bytesから照合。Eの事前frozen-build.jsonはMac private/e-experiment内。公開summaryにもそのhashを保存。原画／GTはMacの`2026-10-12-github-pr-33-4-ocr-https/datasets`から読み取り、全frame hashとmanifestを検査した。

```bash
source runtime/env.sh
(cd repo && gradle --offline --no-daemon :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest)
python3 repo/tools/four-way-evaluator/run.py \
  "$DATASETS/dev-cat" "$DATASETS/dev-watch" "$DATASETS/heldout" \
  --output private/e-experiment/results --adb "$ANDROID_HOME/platform-tools/adb" \
  --device emulator-5580 --label E-fixed-89e2a5f --passes 3 \
  --modes v6_rec v6_both e_mlkit_v6 --rotate-order --record-environment --skip-components
python3 repo/tools/e-evaluator/analyze.py \
  --datasets "$DATASETS" --results private/e-experiment/results \
  --labels private/strata-labels.json --frozen-build private/e-experiment/frozen-build.json \
  --output repo/docs/experiments/e-mlkit-v6-20261013
```

Android JUnit253件（E専用16件含む）全成功、app/test APKビルド成功。16件は行欠落、弱いprobability、ML Kit confidence混同、数字／否定の弱い変更、無関係文、離れた行、名札単独、短い発話・同じ字高の字幕、上下対称の除外を検査。通常APK同一、E dex通常APKなし／test APKありも検査した。27run全891画像でGT ID/mono_ms/文字列、画像／APK hash、edit distanceとfactory/call gateを検査。独立component診断は今回再実施しておらず、その単体時間を新しいE測定と混ぜない。

## 判断

Eの固定実装ではCER 7.07%で、Bより3.69pp改善、Dより1.45pp高い。既知99枚での精度・速度の折衷として評価する。前回の5.93%はGT oracleで、今回値との差はGTなしの実ルールで何を採用できたかの差。結果を見て追加調整せず、失敗も保持した。未知動画で精度維持を検証するまで通常アプリへ採用しない。D固定/P1〜P4終了は維持し、mainマージ・APK Release・Galaxyアプリ更新は行っていない。

## 結果の要点と残る失敗

EはBの274 editsを180へ減らし、**94 edits、34.3%減**。Dは143 editsなので、EにはDより37 edits多く残る。完全一致はB66/99、D78/99、E77/99。EがBより改善した画像は13、字幕comparisonKeyのedit distanceが悪化した画像は0だった。これは既知99枚の評価で、一般動画での無悪化保証ではない。

名札bandが最終出力から消えた8画像で64 edits、v6修正を新たに採用した5画像で30 edits（猫16・移行14）を減らした。Eがraw入力から除外した13行には、もともと最終字幕になっていなかった背景も含むので、13行を13改善画像とみなさない。全99枚1反復のv6 Rec呼出はB231、D472、E223回。Eのv6 Detは0回。追加ルールの平均時間は猫3.28ms、時計0.65ms、移行2.88ms/画像で、full pipeline時計に含まれる。

**Eの速度はBと同じ範囲だが、完全に同一ではない。** 共通warmの中央値B233ms、E237ms、D622ms。動画別中央値は猫B329/E311/D867、時計B147/E149/D337、移行B225/E237/D629ms。Eの中央値はDの約36〜44%の時間で、Bの約95〜105%。平均でEが僅かに速いことは、推論回数減少に加えhost負荷変動の影響があるため、Eが常にBより速いとは主張しない。猫Eのp95は507msでB468msより大きく、tail改善の保証もない。

前回のB178/111/166ms、D466/258/471msとは実行時間が異なる。今回は別AVDも接続されており、全方式で時計が増えた。同時期・同じ試験APK・循環順序で測った今回のB/D/Eを直接比較し、前回Bと今回Eの速度を比較しない。
