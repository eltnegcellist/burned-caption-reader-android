# Indra失敗原因の判別：字幕位置か、映像上の文字認識か

**判別：字幕位置の問題だけでは説明できず、縁取り・背景に対する認識側の弱さを確認した。Eの検出矩形へ置き換えるだけでは解決しない。ただし「白背景の黒文字しか読めない」「Indraでは原理的に採用不可能」とまでは言えない。**

**10/21の続報：** [白・黒抽出を別々に認識して信頼度で選ぶ追試](indra-white-black-extraction-20261021.md)では、実99画像のCERが9.86%→8.96%、完全一致が39→53枚へ改善した。以下の9.86%は白抽出のみの条件として保持する。

2026-10-20、[99画像の主試験](indra-e-mac-private99-results-20261020.md)に続いて、検出器を使わず認識器へ矩形を直接渡す診断を行った。通常アプリ・Eの実装は変更していない。元画像・正解文・OCR全文は引き続き非公開。公開する[追加集計JSON](indra-e-mac-private99-20261020/recognition-cause-summary.json)は数値と条件説明だけである。

## 1. Eの字幕位置に置き換えれば読めるか

元の99画像・2,545正解文字・凍結SHAを再利用した。E保存JSONの`recognition_rows`から、Eが選択した字幕bandの上下範囲に行中心が入るML Kit行矩形を取り、元画像の画素座標へ戻した。この214行矩形をIndraの`recognize()`へ直接渡した。

**Indraの位置検出・方向判定は実行していない。** 行の上下・左右位置はE由来で、GTは位置選択に使わない。Eの認識文へのfallbackもなく、Indraで読めなければ空出力のまま採点する。E側で矩形が残らなかった11画像も除外せず、空として99画像の分母に含めた。

|99画像の経路|編集数 / 2,545文字|CER|完全一致 / 99|字幕ありで空 / 87|
|---|---:|---:|---:|---:|
|E 保存済み|180|7.07%|77|2|
|Indra 全画面・回転OFF（主試験）|1,856|72.93%|21|10|
|**Eの位置 → Indra標準認識・元画素**|**1,476**|**58.00%**|**27**|**22**|
|Eの位置 → 全画面白黒反転 → Indra標準認識|755|29.67%|27|2|
|Eの位置 → 白文字抽出 → Indra標準認識|744|29.23%|25|3|
|Eの位置 → 元画素 → CJK認識器固定|814|31.98%|27|3|
|Eの位置 → 反転 → CJK認識器固定|522|20.51%|27|2|
|**Eの位置 → 白文字抽出 → CJK認識器固定**|**251**|**9.86%**|**39**|**3**|

位置の置換で改善する部分はあるが、そのままの認識器置換ではCER 58.00%が残る。Eの位置で認識した214行のうち113行が信頼度0.5未満となり、Indraから空文字列として返された。**「位置検出モデルだけEへ戻せば解決する」という仮説は、この経路では成立しない。**

元画素・単純反転の2条件は画像ごとに3反復して文字列一致を確認した。白文字抽出＋CJK固定は探索後に別途99画像×3反復で確認し、3回とも初回探索と全文が一致した。ほかの補助条件は各1回の探索であり、3反復済みの主試験と区別する。

ここでの「Eの位置」は保存済みの粗検出行矩形と字幕bandを使ったオフラインの差し替え診断。Eのrefine内で再検出した矩形やAndroidの全画素前処理を完全再現した新アプリの実測ではない。速度・TTS・ライブ状態の評価は行っていない。

## 2. 正しい位置を与えても背景・装飾で失敗するか

既存の注釈40画像のうち、字幕矩形がある**32画像・85行・925文字**を使った。各注釈行の本文を順に連結した比較キーは、元の各画像の正解文と完全一致する。矩形は今回のIndra結果を見る前から保存されていたもの。位置検出は完全に省略し、同じ矩形で画素条件だけを変えた。

|同一32画像・925文字の条件|CER|完全一致 / 32|空の行 / 85|
|---|---:|---:|---:|
|E 保存済み（この32画像のみ）|7.78%|23|対象外|
|注釈位置＋元画素＋Indra標準認識|31.57%|4|22|
|注釈位置＋単純反転＋Indra標準認識|11.24%|5|4|
|注釈位置＋白文字抽出＋Indra標準認識|3.46%|13|0|
|注釈位置＋元画素＋CJK固定|20.76%|4|13|
|注釈位置＋白文字抽出＋CJK固定|2.38%|15|0|

正しい位置を与え、方向判定もなくした条件でも元画素では失敗が残る。同じ実画像の文字画素を抽出すると改善するため、検出器以外の画素前処理・文字の見え方・認識が原因に含まれることを確認できる。注釈位置は理想的位置を与える診断であり、これらの低いCERを自動字幕リーダーの性能として扱わない。99画像全体とも分母を混合しない。

参考に、前の段階診断でも85注釈矩形のうち82矩形にはIoU≥0.5で対応するIndra検出矩形があった。そのうち58矩形は、重なる認識候補がすべて信頼度0.5未満で空だった。位置の重なりだけでは正しい切り出し・認識を保証しないが、「文字がある場所を全く見つけていない」だけではないことと整合する。

## 3. 白背景専用なのか、縁取り・背景が問題なのか

上と同じ非公開925文字・85行を、Hiragino Gothic W3・42pxで再描画した。位置は既知の描画矩形を直接渡し、検出器・回転判定を使わない。CJK認識器へ固定して、自動文字種判定による違いも取り除いた。

|同じ文字列・フォントの描画条件|CER|空の行 / 85|
|---|---:|---:|
|白背景に黒文字・縁取りなし|0.22%|0|
|黒背景に白文字・縁取りなし|0.22%|0|
|白背景に白文字＋黒縁3px|24.97%|6|
|映像由来の明暗背景に同じ白文字＋黒縁3px|79.78%|68|

縁取りのある後半2条件は、文字画素・位置・大きさを共通にし、背景だけを変えた。映像背景は同じ元フレームを16×16へ縮小してから拡大した明暗テクスチャで、元の細かい文字を読み直す条件ではない。

**単純な白黒反転には対応できる一方、縁取りと映像背景によって、位置が既知でも認識が大幅に崩れる。** したがって「白背景の黒文字専用」という説明は正確ではない。これは制御した合成診断であり、そのCERを実動画のCERとして報告しない。フォント・サイズの一般性や、縁取りと背景が各動画で占める誤りの割合までは確定していない。

## 4. 何が改善し、採用判断に何が残るか

白文字抽出は既存アプリの`OcrBitmapInputs.whiteCore()`と同じ固定規則をPythonで再現した。RGBの最小値≥210、最大値−最小値≤45の画素を黒、その他を白にする。今回の正解を見て閾値を調整したものではない。元画像・通常アプリは書き換えていない。

CJK固定はパッケージに同梱される日本語等のCJK認識器を直接使い、標準の文字種分類器によるbase/他の認識器への振り分けを省く診断。内部`recognize(..., vertical=True)`のCJK経路を呼ぶが、ここでは画像を回転していない。元画素で58.00%→31.98%、白文字抽出後でも29.23%→9.86%となり、標準の自動振り分けも出力差に寄与する。

Indra 1.1.2が指定する固定モデルv1.1.0、commit `bd02167fdf2005a19962cc15188f8496a2c87d3b`、4 threads、同じMac環境を継続使用した。モデルセットには`mask.onnx`がなく`rec_window=3`であるため、集計JSONに残したno-mask対照は同一結果の無操作対照であり、CenterMaskが原因だったと解釈しない。

二つの仮説への回答は次のとおり。

- **位置だけの問題か：否。** Eの位置でも元画素の認識が崩れる。位置・切り出しの違いにも改善余地はあるが、それだけでは済まない。
- **背景や装飾に弱いのか：今回の縁付き白字幕では確認できた。** 位置・認識器を固定した対照でも再現した。ただし白背景専用ではなく、前処理とCJK固定によって実99画像も改善する。
- **そのまま採用できるか：今回の単純置換はEを下回る。** 追加処理ありでもCER 9.86%対7.07%、完全一致39対77枚、空出力3対2枚。現行Eを変更する根拠にはしない。一方、画素前処理後には読めるため、「認識器として原理的に不可能」と断定する根拠もない。

本診断は既知99画像を見た後の探索であり、未知動画での検証ではない。実用化を検討するなら、色付き字幕・白い背景物体・異なる縁取りでも白文字抽出が字幕を壊さず機能するか、CJK固定が対象言語に適切かを別素材で確認する必要がある。今回、製品への組込みや性能改善の実装は行っていない。
