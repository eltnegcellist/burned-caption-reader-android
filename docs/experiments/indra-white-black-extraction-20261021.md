# 白文字・黒文字の両抽出でIndraの精度が改善するか

**今回の既知99画像では改善した。白・黒を別々に認識し、行ごとにIndraの信頼度で選択すると、CERは9.86%→8.96%、完全一致は39→53枚となった。正解による選択は使っていない。** 改善16枚・悪化0枚・同じ83枚。各条件3反復で出力が一致した。一方、現行EのCER 7.07%・完全一致77枚には届いていない。

[前の原因分離試験](indra-detection-vs-recognition-20261020.md)と同じ非公開実99画像・2,545正解文字・保存済みEの位置を使った。元画像、正解、OCR全文、画像別IDは公開せず、[集計JSON](indra-white-black-extraction-20261021/summary-only.json)と分析だけを追加する。通常アプリ・E方式は変更していない。

速度は[別の対比較計測と各工程の内訳](indra-white-black-latency-20261021.md)を参照。Macでの後段処理のみでは白抽出16.76ms→両抽出24.71ms（中央値）だった。Eの検出を含むAndroid全体の速度ではない。

## 固定した処理と、両抽出の組合せ

- 位置はE保存JSONの`recognition_rows`から、Eの選択band内に行中心がある矩形を使用。99画像・214行。位置選択にGTは使わず、Eの認識文へのfallbackも行わない。矩形がない11画像も空として採点する。
- Indra 1.1.2、固定モデルv1.1.0、4 threads、同梱CJK認識器を直接使う。Indraの位置検出・方向判定は省略し、画像は回転しない。モデル・入力のSHAとE baseline 180/2,545の検証を再実行した。
- **白抽出**：RGB最小値≥210、最大値−最小値≤45の画素を黒、それ以外を白。既存`whiteCore()`と同じ規則。
- **黒抽出**：RGB最大値≤45、最大値−最小値≤45の画素を黒、それ以外を白。RGBを反転して白抽出をかける規則と対称で、今回の正解に合わせて閾値を探索していない。
- 両抽出の各画像を**それぞれOCR**する。行ごとに、片方だけ正規化後の文字列があればその側を採用。両方に文字列があればIndraのCTC平均信頼度が高い側を採用し、同点なら白側。両方空なら空のまま。GT・E文・動画名をこの選択関数へ渡さない。
- 比較用に、白側が空の行だけ黒側へ切り替える規則と、白・黒の抽出画素を一枚へ合併してからOCRする規則も事前固定して試した。しきい値の境界・色条件・白黒対称性・選択の同点/空処理を小さな合成入力で確認してから実データを実行した。

## 黒文字の対照試験

実99画像には今回新たな文字色ラベルを付けていないため、「実際の黒字幕全体での精度」は別集計できない。そこで、既存注釈32画像の同じ非公開925文字・85行をHiragino Gothic W3・42pxで描画した。文字位置は描画矩形として固定し、認識器もCJKに固定した。映像由来背景は元フレームを16×16に縮小して拡大したテクスチャ。これは**合成の対照試験**であり、実99画像のCERと混合しない。

|合成描画条件 / 925文字|白抽出のみ CER|黒抽出のみ CER|両認識＋信頼度 CER|
|---|---:|---:|---:|
|白背景・黒文字、縁取りなし|0.43%|0.43%|0.22%|
|黒背景・白文字、縁取りなし|0.43%|0.43%|0.22%|
|映像テクスチャ・白文字＋黒縁3px|0.76%|42.27%|0.76%|
|映像テクスチャ・黒文字＋白縁3px|36.54%|4.65%|3.57%|

黒文字に白縁を付けた対照でも、白側だけより両認識が大きく改善した。一方の極性の画素だけでは、文字本体ではなく縁取りを拾って誤認識する場合がある。白・黒候補を別々に残すと、文字色に応じて補完できることと整合する。白地の黒文字へ白抽出を適用しても必ず全滅するわけではなく、反転した文字形状が残ることもこの対照で確認できた。

## 正解が分かっている場合の上限と限界

実用の信頼度規則とは別に、GTを使って二候補のうち良い方を選ぶ診断も計算した。

|GTを使う診断 / 実99画像|編集数|CER|完全一致|
|---|---:|---:|---:|
|画像ごとに白だけ/黒だけの良い方を選ぶ|202|7.94%|56/99|
|行ごとの白/黒の組合せを全探索して選ぶ|200|7.86%|56/99|

**この二つは正解を知るoracleであり、実装可能な方式の実測として扱わない。** 行ごとの組合せは最大4行・16通りで、今回の二候補と固定行順に限定した上限である。信頼度規則の228 editsに対して選択を改善する余地はあるが、この候補集合のoracleでもEの180 editsには届いていない。文字単位での合成や別の前処理まで含めた上限ではない。

今回の改善は、しきい値と規則を事前固定したうえでの既知素材上の探索結果。未知動画での再現性、信頼度の校正、色付き字幕・明暗が変わる背景への一般性は未確認。二つの抽出を別々に認識するため、認識処理も追加されるが、この追試では処理時間を比較していない。通常アプリのE方式は維持する。
