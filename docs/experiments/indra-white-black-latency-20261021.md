# 白抽出と白・黒両抽出：速度と各工程の内訳

**同じMac上の後段処理は、白抽出のみが中央値16.76ms、両抽出＋信頼度選択が24.71ms。約1.47倍で、中央値の差は7.95msだった。** これはEの検出結果を受け取った後の抽出・Indra認識・選択だけの時間。**Eの検出器を含むAndroidアプリ全体の速度ではない。**

[精度試験](indra-white-black-extraction-20261021.md)と同じ実99画像・2,545正解文字・E由来214行矩形を使用。タイミング中の全文は、白抽出CER 9.86%と両抽出CER 8.96%を出した前回の各画像出力とすべて一致した。画像・正解文・OCR全文・画像別IDは公開せず、[匿名の全体/動画別/工程別集計](indra-white-black-latency-20261021/summary-only.json)だけを追加する。通常アプリのE方式は変更していない。

## 同じMac内での比較

Apple M4 / 16GiB、macOS 26.6.2、Python 3.14.4、Indra 1.1.2、ONNX Runtime 1.31.0、4 threads、固定モデルv1.1.0。CJK認識器へ直接渡すためIndraの位置検出・回転判定は使わない。

RGB画像とEの行矩形を先に読み込み、モデルを一度ロードした。白のみ・両方の完全な経路を各1回warm-upした後、99枚を3周した。各画像で白のみ→両方、両方→白のみの順を交互にし、計297対（白先行149、両方先行148）を測定。両経路でOCRを実行し、白側の認識結果をもう一方の経路へ流用しない。

|集計対象|白抽出のみ 中央値 / p95|両抽出＋信頼度 中央値 / p95|
|---|---:|---:|
|99枚×3回＝各297観測|16.76 / 19.10ms|24.71 / 29.17ms|
|矩形がある88枚×3回＝各264観測|17.05 / 19.11ms|24.92 / 29.23ms|

99枚にはEの字幕行矩形がない11枚も含む。この11枚は両経路とも抽出・認識を省略し、空出力へ直ちに戻る。検出に時間がかからなかったという意味ではない。p95は個々の実測値をpoolしたnearest-rankで、以前の主試験の「画像内中央値のp95」とは集計方法が違う。

全297対の画像ごとの時間差（両方−白のみ）は中央値7.58ms、平均6.83ms。二つの全体中央値の差7.95msとは別の統計である。

## 各工程の内訳：Macネイティブの後段

**以下は矩形がある88枚・各3回の1画像あたり平均ms。** 平均の内訳は足せるが、各工程の中央値やp95を足して全体中央値にしない。

|工程|白抽出のみ|白・黒両抽出|
|---|---:|---:|
|共通のRGB最小/最大・無彩色判定|8.896|8.915|
|白文字maskの作成|0.316|0.315|
|黒文字maskの作成|0|0.278|
|白側のIndra文字認識|7.586|7.617|
|黒側のIndra文字認識|0|7.326|
|信頼度での選択・最終文字列の結合|0.001|0.029|
|**平均合計**|**16.799**|**24.480**|

平均の増加は7.680ms。主な追加費用は黒側の文字認識で、黒mask作成と候補選択の費用は小さい。RGBの共通走査を白・黒で共有するため、全体が単純に2倍にはならなかった。ここでいう文字認識時間には、Indra内部の行crop・リサイズ・モデル推論・CTC復号を含む。ネットワーク推論だけの時間ではない。

抽出は1080×608/609の元フレーム全体へNumPyで実施し、その後Indraへ既知の行矩形を渡している。RGB走査が約8.9msを占めることはこの実装の値であり、字幕ROIだけを処理する実装やAndroid上の費用を測ったものではない。

## Eの既存Android結果の内訳（別環境の参考値）

保存済みのE実行9件（3区分×3反復）から、既存の`cold_indices`でframe0とlazy-initのある画像を除外した285 warm観測を再集計した。全体中央値237ms・p95 373ms、平均229.046msを再現した。

|Eの工程|1画像あたり平均ms|
|---|---:|
|ML Kit公開OCR：位置検出＋粗文字認識、再呼び出しを含む|50.774|
|PP-OCRv6文字認識|146.170|
|画像・字幕bandの切り出し/リサイズ|7.069|
|候補・修正選択など（E policy以外）|7.350|
|E policy|2.384|
|dispatch・行crop・並べ替え・consensus・診断等の残差|15.297|
|**平均合計**|**229.046**|

EではPP-OCRv6の検出モデルは呼ばれておらず、その計測時間は0。ML Kitの公開APIは検出と粗認識を一体で返すため、このログから検出器だけの時間へ分離できない。E policyは元ログのselection時間に含まれるため、上表ではselectionから差し引いて別表示し、二重加算していない。各工程の中央値・p95と区分別値も集計JSONへ保存した。

**237ms対24.71msを速度倍率にしたり、EのML Kit時間をMacのIndra時間へ足して新アプリの速度を推定したりしない。** Eは以前のAndroid ARM64エミュレーターの全OCR pipeline、今回のIndraはMacネイティブの後段のみで、処理範囲・環境・測定時期が違う。

## 別枠の費用と未測定部分

- モデルloadは今回366.03ms（キャッシュ済みモデルを`indra_ocr.load()`する一度の実測）。上の定常処理時間には含めない。
- 事前のPNG読込＋decode＋RGB変換は99枚各1回で中央値7.48ms・p95 8.62ms・平均7.44ms。これは保存画像の読込であり、実動画の画面取得時間ではない。上の後段時間には含めない。
- 実測時刻は2026-10-21 06:51:11〜06:51:22 JST。前後ともAC接続、温度・性能警告の記録なし。実CPU温度・消費電力・他プロセス負荷は計測/統制していない。
- Eの検出・字幕band選択、画像取得、Androidの連携費用、TTS待ち・可聴開始は新しい経路では未測定。Galaxy S25上での全体速度を確定するには、端末上の経路を別途実装・計測する必要がある。
