# ML Kitの位置検出を外す場合と、位置検出を全廃する場合の精度

**ML Kitを外し、白文字抽出後の画像をIndra自身で検出すると、白・黒両認識のCERは10.29%、完全一致46/99枚だった。** E由来の位置を使う8.96%・53/99枚から全体では悪化するが、元画素の標準Indra・回転OFFの72.93%まで戻るわけではない。**位置検出をすべて省いて全画面を1行として認識器へ渡す条件はCER 100.31%となり、使える精度ではなかった。**

[公開集計JSON](indra-without-mlkit-20261021/summary-only.json)。元画像、正解文、OCR全文、画像別ID、モデルは非公開を維持し、通常アプリのE方式を変更していない。

## 共通条件と二つの「省略」

元99画像・2,545正解文字・全PNG/manifest SHA・E baseline 180 editsを比較スクリプトの検証で確認した。Indra 1.1.2、同梱モデルv1.1.0、4 threads、CJK認識器固定、同じ白抽出（min RGB≥210）・黒抽出（max RGB≤45）を使用。無彩色条件は最大RGB−最小RGB≤45。白・黒は別々に認識し、正規化後に片方だけ文字があればその側、両方あればCTC信頼度が高い側を選び、同点なら白側を採用した。GTは採点のみに使用する。

今回は推論関数へRGB画像と固定の方式名だけを渡した。**E/ML Kitの行矩形、字幕band、GT矩形、dataset名、画像IDは推論・候補選択に渡していない。**

1. **ML Kitだけを外す条件**：Indraの`detect()`で全画面から行矩形を得て、抽出画像を`recognize()`へ渡す。検出入力を元グレースケール、白抽出、白・黒両方で比較した。白・黒の検出矩形を統合する条件は白側の矩形を先に保持し、IoU≥0.5で重なる黒側の矩形を除いた。
2. **全位置検出を外す対照**：EもIndraの検出器も呼ばず、[0,0,幅,高さ]という全画面1矩形を行認識器へ渡す。字幕位置を推測した矩形ではなく、複数行の画像を1行入力として扱う対照である。

全条件で画像を回転せず、方向モデルも使わない。矩形は上→下、左→右に並べ、前のE矩形試験と同じ幾何的な順で連結した。通常Indra APIのレイアウト/読書順モデルは使わない。

**Eの字幕候補選別も移植していない。** Indraが検出した全行を読むため、名札・章題などが余分に出力へ入る可能性がある。この比較はML KitとE字幕選別を使わない経路の評価であり、検出ネットワーク単体の性能差ではない。

## 精度：実99画像・2,545文字

|経路|編集数|CER|完全一致 / 99|字幕ありで空 / 87|字幕なしで誤出力 / 12|
|---|---:|---:|---:|---:|---:|
|E 保存済み|180|7.07%|77|2|3|
|Eの位置＋白・黒両認識（前の試験）|228|8.96%|53|3|3|
|Indraで元画像を検出＋白抽出認識|453|17.80%|17|1|3|
|Indraで元画像を検出＋白・黒両認識|489|19.21%|21|1|4|
|Indraで白抽出画像を検出＋白抽出認識|273|10.73%|41|1|4|
|**Indraで白抽出画像を検出＋白・黒両認識**|**262**|**10.29%**|**46**|**1**|**4**|
|白・黒両抽出をIndraで検出・矩形統合＋両認識|637|25.03%|24|1|4|
|全検出を省略・全画面1矩形＋白認識|2,552|100.28%|9|71|3|
|全検出を省略・全画面1矩形＋両認識|2,553|100.31%|8|63|4|

7つの新条件を各画像3回、計2,079 frame-method評価で実行し、各条件の全文は3回とも一致した。方式の順番を画像/反復ごとに循環させた。画像ごとにGTで良い方式を選んだ結果ではなく、事前固定した各方式の全99枚の結果をすべて示す。

全検出省略では、字幕あり87枚の完全一致は両条件とも0枚。表の完全一致9/8枚は字幕なし画像の空出力による。CERが100%を超えるのは余計な出力による挿入誤りも加わるため。Indraのこの認識器は行矩形を切り出して一定高さへリサイズする行認識器であり、複数行の全画面を1行として与える使い方には適さない。

## ML Kitなしの最良条件は、どこで変わったか

今回試したML Kitなしの固定条件で最小CERだった「白抽出でIndra検出→白・黒両認識」と、E位置を使う前回条件を比較する。

|区分|E位置＋両認識 CER / edits|Indra位置＋両認識 CER / edits|完全一致 E位置→Indra位置|
|---|---:|---:|---:|
|dev-cat 28枚|5.54% / 47|16.84% / 143|17→8|
|dev-watch 28枚|8.54% / 48|6.76% / 38|26→23|
|heldout 43枚|11.73% / 133|7.14% / 81|10→15|

全体で34 edits増（CER +1.34ポイント）。画像単位では改善19・悪化29・同じ51枚であり、全動画で一律に悪くなったわけではない。字幕あり空出力は3→1枚と減る一方、字幕なしでの誤出力は3→4枚へ増えた。

既存の非字幕文字boxがある40画像で、既知ラベルが正解より余分に含まれる文字列照合をすると、E位置の経路は3/40、Indra位置の経路は8/40。猫の注釈11枚では1→6枚となり、名札などの混入が差の一因と確認できた。未注釈59枚を混入0と扱わず、この診断を全背景誤りの網羅的な監査とは呼ばない。

位置を白・黒双方で検出して矩形を増やすと1,016行となり、白側だけで検出する404行より悪化した。行数を増やすだけでは字幕の精度は上がらない。白・黒の信頼度選択も、白側検出の条件内では白認識のみより20画像改善・11画像悪化・68画像同じだった。前のE矩形固定時に悪化0枚だったことを、別の検出矩形へ一般化しない。

RGB画像読込とモデルloadを除き、抽出→Indra検出→認識→信頼度選択→結合まで測定した。各方式を1回warm-upしてから、実99枚×3回の個々の観測をpoolした。Android上のEとの直接の速度倍率は示さない。

## 判断と未測定事項

**ML Kitは省けるが、今回のIndraでは行の位置を得る処理そのものは残す必要がある。** 前処理とCJK固定によって、ML KitなしでもCER約10%の経路は得られた。ただし現行EやE矩形を使う経路と同等の字幕精度を証明したわけではない。Eの字幕選別をIndraの行出力へ接続した場合の精度は今回未測定であり、悪化分を検出器だけへ帰属させない。

これは既知3動画で複数条件を比較した探索で、独立した未使用素材の検証ではない。Galaxy S25、Androidへの実装、動画の字幕イベントの取り逃し、TTS・可聴開始、長時間動作は未測定。Macのこの全画面経路の時間を、そのまま端末や通常アプリの時間としない。
