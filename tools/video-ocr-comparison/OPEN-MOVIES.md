# 公開映画の日本語字幕OCR比較（2026-10-12～13）

Elephants DreamとSintelの先頭5分をそれぞれ日本語字幕付きMP4へ変換し、VSE・VideOCR・公式Subtitle Edit 5.2.0 GUI（Apple Vision）とAndroid hybridのMP4再生を実行した。公式ソース部品の補助実験も別記録で保持した。さらに同一PixelCopy PNG 70枚で4エンジンを比較した。hybridには検出漏れと候補選択による欠落があり、既存の検出補助・選択処理をまず改善候補にする。Subtitle Editの同一行断片の再配置は、同じOCR観測で画像CERを改善した。一方、重複判定を厳しくする設定の丸採用は見送る。

2026-10-13にMacのロック解除後、Subtitle Edit GUIの2本各5分の抽出とSRT保存を完了した。公式5.2.0の8ファイルを未変更でリンクした補助実験はGUI成績と区別する。Androidは検証専用ローカルMP4経路と既存hybrid部品で比較する。Galaxy S25の速度、YouTube再生、実際のTTS完了は今回の測定対象ではない。

## 入力と実験の固定

|入力|役割|尺・画素|字幕イベント|明示的2行|字幕なし時間|
|---|---|---|---:|---:|---:|
|Elephants Dream|調整用|0～300秒、960×540、24fps|33|7|225.538秒|
|Sintel|未使用検証用、設定変更なし|0～300秒、960×408、24fps|17|0|248.682秒|

映像はCommonsの正規配布URLから取得したCG映画。配布日本語TimedTextをこちらで焼き付けたもので、元から日本語字幕のある実写テロップではない。字幕はHiragino Sans W4、FontSize=24、Outline=2、MarginV=20。フォントサイズの指定は同じでも映像の高さが違うため文字の実画素高は異なる。ffmpegのフォント選択ログも保存した。

OCRを実行する前に、全50字幕イベントの中間画像と字幕なし20画像をCodexが目視確認した。SRTの内容・改行と描画が一致し、OCR出力から正解は作っていない。独立した人間による二重確認は未実施。開始・終了の正解は焼き付け元SRTで、24fpsの描画量子化による最大約41.7msの不確かさを含む。全フレームの字幕境界を人手確認したとは主張しない。

共通手動ROIは映像の下180px。字幕なしでも同じROIを与える。字幕領域を絞っても、この範囲に入る英語タイトルは正解字幕に含めず、余分な出力として採点する。手動ROIと自動領域選択の成績を混ぜない。入力SHA-256・参照SRT hash・画像hashは`open-movies/benchmark-inputs.json`、数値の正本は`open-movies/benchmark-metrics.json`。

合成コントロールで候補になったVSE text-similarity 100、VideOCR tight-box SSIM 1.0を事前に固定し、既定80/0.85と比較した。Sintelの出力を見て候補やしきい値を追加・変更していない。同じBlender系CG映画2本だけで実写への一般化を主張しない。3本目Cosmosは配布サーバーHTTP429で未取得。

- Elephants DreamのVSE：固有名詞「イーモ」の誤読が1イベント。2行の文字は取得するがSRTは行をスペース結合し、原文どおりの改行は0/7。

### 実験A：同一PixelCopy画像

Android再生中のPixelCopyから、OCR前に固定した50字幕中間時刻・20空白時刻に最も近い画像を選んだ。成功・失敗で選別せず、全70 PNGを目視確認して正解を凍結した。全エンジンでmanifest・各PNG SHAが一致し、Android端末上でも転送後のPNG SHAを照合した。SE/VSE/VideOCRは独立デコードしたROI RGB hashも一致した。手動ROIでも検出器＋認識器を使用し、純粋な文字decoderだけの評価ではない。ROIが英語クレジットを含む場合、それも余分な出力として採点する。

hybridのElephants手動ROIで空になった4画像はbackendがML Kitのままで、文字枠が得られずPP-OCRの文字認識へ進んでいなかった。2行画像の1枚では上段が欠けた。VSEとhybridはいずれもPP-OCRv5 mobile認識を使うが、検出器・入力画像・runtime・選択が違うので、差を「新しい認識モデルへの交換で改善できる」と断定しない。`一人`を`ー人`と読む例、数字の`一`が欠ける例もある。否定語・固有名詞・数字の網羅的なカテゴリ成績は未測定で、サンプルを増やして確認が必要。

### 同一OCR観測で確認したSEの技術

SEの`AppleVisionTextLayout.Compose`を未変更で呼び、同じVision観測を単純なy順ソートした文字列も同時に保存した。Elephantsの手動ROIでは**CER7.17→3.40%、完全一致28→30/33、追加OCR0回**。全画面でも10.94→8.68%。Sintelは変化なし。観測の高さの半分以内にある断片を同一視覚行へ戻して左から読む処理が、わずかなyずれによる行順逆転を修正した。モデル・観測・入力を変えて改善した比較ではない。

AndroidにはML Kit行情報、文字ギャップ分割、block/2～3行グループ化が既にある。ただしML Kit行列とPP検出補助のappendはtop→leftのソートで、SEと同じ「同一視覚行の断片を高さ基準で再配置」ではない。移植するなら新OCR枠のadapter層で限定検証する。今回のAndroidに行順崩れが主要因だと証明したわけではない。Androidでの追加ms/MiBは未測定。
